prompt: |
  # Tugas — Mas Obie dan “Wokee, Dana Masuk Boskyuh”

  Mas Obie sedang mengembangkan toko online kecil miliknya. Setiap kali ada pelanggan yang mengaku sudah membayar, Mas Obie perlu memeriksa beberapa informasi sebelum transaksi dianggap berhasil.

  Suatu hari, seorang pelanggan mengirimkan bukti pembayaran berupa:

  `"Wokee dana masuk boskyuh"`

  Mas Obie tentu tidak bisa langsung menganggap pesan tersebut sebagai pembayaran yang sah. Ia membutuhkan program sederhana yang dapat membantu memeriksa transaksi secara konsisten.

  Tugasmu adalah membantu Mas Obie melengkapi program tersebut dengan menerapkan beberapa konsep Python yang telah dipelajari.

  1. Tujuan tugas

  Gunakan:

  - class method
  - static method
  - konsep decorator
  - custom decorator
  - chaining decorator
  - `*args` dan `**kwargs` pada wrapper decorator

  Program harus dapat membuat object transaksi dari teks, memvalidasi kode transaksi, memeriksa bukti pembayaran, dan mencatat berapa kali proses verifikasi dilakukan.

  2. Spesifikasi class `Pembayaran`

  Buat atau lengkapi class `Pembayaran` dengan aturan berikut.

  - `total_transaksi = 0` dan `total_verifikasi = 0` merupakan class attribute.
  - Constructor menerima `(nama, nominal, bukti, kode)`.
  - Simpan `nama`, `nominal`, `bukti`, dan `kode` sebagai public attribute.
  - Simpan status transaksi pada private attribute `__status`.
  - Status awal setiap transaksi adalah `"PENDING"`.
  - Setiap object `Pembayaran` yang berhasil dibuat harus menambah `Pembayaran.total_transaksi` satu kali.

  3. Class method

  Buat:

  `@classmethod dari_teks(cls, teks)`

  Method menerima teks dengan format:

  `nama nominal bukti kode`

  Contoh:

  `Budi 150000 TRANSFER_VALID P001`

  Ketentuan:

  - Pecah teks menjadi beberapa bagian.
  - Ubah `nominal` menjadi integer.
  - Gunakan `cls(...)` untuk membuat dan mengembalikan object baru.
  - Nama dan bukti menggunakan underscore apabila terdiri dari beberapa kata.

  Contoh:

  `Mas_Obie 150000 Wokee_dana_masuk_boskyuh P001`

  harus menghasilkan object dengan:

  - `nama = "Mas_Obie"`
  - `nominal = 150000`
  - `bukti = "Wokee_dana_masuk_boskyuh"`
  - `kode = "P001"`

  4. Static method

  Buat:

  `@staticmethod kode_valid(kode)`

  Method mengembalikan:

  - `True` jika kode terdiri dari huruf `P` diikuti tepat tiga digit.
  - `False` untuk format lainnya.

  Contoh:

  - `P001` → `True`
  - `P123` → `True`
  - `P12` → `False`
  - `X001` → `False`

  Method ini tidak boleh menggunakan `self` maupun `cls`.

  5. Property status

  Gunakan property untuk mengakses status transaksi.

  Buat:

  `status`

  yang mengembalikan nilai dari private attribute `__status`.

  Status hanya boleh berubah melalui proses verifikasi.

  6. Custom decorator pertama

  Buat decorator:

  `hitung_verifikasi(func)`

  Decorator harus memiliki wrapper dengan bentuk:

  `wrapper(*args, **kwargs)`

  Ketentuannya:

  - Teruskan `args` dan `kwargs` ke function asli.
  - Jalankan function asli.
  - Setelah function selesai, tambah `Pembayaran.total_verifikasi` satu kali.
  - Kembalikan hasil dari function asli.

  Artinya, setiap kali Mas Obie mencoba melakukan verifikasi, jumlah verifikasi bertambah satu, baik hasilnya berhasil maupun gagal.

  7. Custom decorator kedua

  Buat decorator:

  `hasil_boolean(func)`

  Decorator juga wajib menggunakan:

  `wrapper(*args, **kwargs)`

  Ketentuannya:

  - Teruskan seluruh `args` dan `kwargs` ke function asli.
  - Ambil hasil dari function asli.
  - Pastikan nilai yang dikembalikan berupa boolean.

  Contoh:

  - `True` tetap menjadi `True`.
  - `False` tetap menjadi `False`.

  8. Chaining decorator

  Gunakan kedua decorator pada method:

  `verifikasi()`

  dengan chaining:

  `@hitung_verifikasi`
  `@hasil_boolean`

  Method `verifikasi(self, catatan="")` harus mengikuti aturan:

  - Pembayaran valid jika `nominal > 0`.
  - Kode transaksi valid menurut `kode_valid()`.
  - Bukti pembayaran harus tepat `"TRANSFER_VALID"`.
  - Jika semua kondisi terpenuhi:
    - ubah status menjadi `"VALID"`
    - kembalikan `True`
  - Jika salah satu kondisi gagal:
    - ubah status menjadi `"DITOLAK"`
    - kembalikan `False`

  Parameter `catatan` tidak digunakan untuk menentukan valid atau tidaknya pembayaran. Parameter ini digunakan agar program utama dapat memanggil method dengan keyword argument dan membuktikan bahwa wrapper benar-benar meneruskan `**kwargs`.

  9. Program utama dan output

  Jangan mengubah program utama.

  Input memiliki format:

  `nama nominal bukti kode`

  Program utama akan:

  1. membuat teks transaksi,
  2. membuat object menggunakan `Pembayaran.dari_teks(...)`,
  3. menjalankan `verifikasi(catatan="otomatis")`,
  4. menampilkan hasil transaksi.

  Output harus tepat delapan baris:

  - Nama
  - Nominal
  - Bukti
  - Kode Valid
  - Verifikasi Berhasil
  - Status
  - Total Transaksi
  - Total Verifikasi

  10. Aturan pengerjaan

  - Lengkapi bagian `TODO` saja.
  - Jangan mengubah nama class, method, parameter, decorator, label output, atau urutan program utama.
  - Jangan menggunakan inheritance atau library tambahan.
  - Counter `total_transaksi` dan `total_verifikasi` harus diubah pada tingkat class.
  - Kedua decorator wajib menggunakan `*args` dan `**kwargs`.
  - Kedua decorator wajib meneruskan argument ke function asli.
  - Percobaan verifikasi yang gagal tetap dihitung sebagai satu verifikasi.
  - Pesan `"Wokee dana masuk boskyuh"` tidak boleh dianggap sebagai bukti pembayaran yang valid.

  Checklist sebelum Run Tests

  - `kode_valid()` tidak menggunakan `self` atau `cls`.
  - `hitung_verifikasi` menggunakan `*args` dan `**kwargs`.
  - `hasil_boolean` menggunakan `*args` dan `**kwargs`.
  - `kwargs` diteruskan ke function asli.
  - `verifikasi()` menggunakan dua decorator sekaligus.
  - Bukti selain `"TRANSFER_VALID"` menghasilkan `False`.
  - Verifikasi gagal tetap menambah `total_verifikasi`.
